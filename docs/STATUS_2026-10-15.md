## 3. Provider setup

- One provider is wired: Anthropic, through the official `Anthropic` NuGet (12.56.0) exposed as a `Microsoft.Extensions.AI` `IChatClient` (`AsIChatClient` in `src/Agent.Core/Parsing/ParserFactory.cs`). No other provider exists; a second one would be a new `Provider` value in `ModelOptions` and a branch in the factory.
- Parser switch: `Agent:Parser` is `scripted` (default, no key, reads `src/Agent.Core/Parsing/scripted-sentences.json`) or `claude`. Candidate switch: `Model:Candidate` names an entry of `Model:Candidates` (`haiku` default, `sonnet`, `opus`) in `src/Agent.Web/appsettings.json` and `src/Agent.Eval/appsettings.json`, each with model id, max output tokens, effort, timeout and prices. The eval takes `--parser scripted|claude:<candidate>`.
- Key: read from user secrets `Anthropic:ApiKey` (the Agent.Web user-secrets id, shared by the eval runner) or the `ANTHROPIC_API_KEY` environment variable; checked at start, never logged. Wallet client and admin keys follow the same pattern (`Wallet:ClientKey`, `Agent:WalletClientKey`, `Wallet:AdminKey`), with "any non-empty value" accepted in Development only.

Per case it plays every step form (say, tap option, confirm with PIN, cancel, try again, save alias, wait for expiry, faults), then `Grading/CaseGrader.cs` grades questions asked and their options, every card field, replies by reason code, refusals, the final wallet state and the learning-log entry. It also reports, apart from the card score, the red-team mark (executions without a tap, `ExecutionsWithoutTap`), the masking check on every case (`Checks/OutboundTextCheck.cs`), time per case and cost. `Running/HeldOutGuard.cs` refuses the held-out set without `--milestone-11-run` and refuses when the file hash differs from the one in `docs/disclosure.md`.
