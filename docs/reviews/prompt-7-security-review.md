## Findings

### Minor

**M1. No test proves the other-balance guard is wired into `ClaudeParser`.** `OtherBalanceGuardTests` tests the static class; `ParseGuards.Apply` has no test; the only proof that the model parser applies the guard is the one line in `ClaudeParser`, and `ClaudeParserTests` has no guard test (nor one for the dinar guard, pre-existing). A refactor that dropped `ParseGuards` for `DinarUnitGuard` would pass every test. Fix: one test in `ClaudeParserTests` with the fake chat client returning a `balance` with a `recipient_text` and asserting the parsed request is `Unsupported` with `other_balance`; optionally the same for a bare amount with a dinar word.

**M2. Neither guard leaves a trace step when it rewrites a request.** `Conversation` records `parse:<parser>` with the guarded intent (`Unsupported`), so the live trace of a RED-10 read as `balance` shows no sign that the model said `balance` and code corrected it. The design's probe "reads the parse in the probe's trace", which the trace cannot show today (the disclosure says the probe was done by direct parses instead). Fix: the parsers record `TraceZone.Code`, `guard:other_balance` (and `guard:dinar_unit`) when the guarded list differs from the validated one, or `ParseGuards.Apply` takes the trace. Small, and it makes the Learning data panel's `not_supported`/`other_balance` rows explainable.

**M3. seed-v5 is not tagged.** Tags `seed-v1` to `seed-v4` exist; no `seed-v5` ref. `data/seed/README.md`'s re-freeze procedure says "tag the new seed", and the disclosure's seed line reads "tags `seed-v1` to `seed-v4`; seed-v5, 4 Nov 2026". The design says no tag for the round. For Khalil: either tag `seed-v5` at c00b1c9 when merging, or add one sentence to the README and the disclosure saying seed-v5 is named in the hash file and the disclosure and tagged with the freeze. Traceability for the organisers, not a security matter.

### Notes

- **N1.** The guard's failure is on the safe side: a model that fills `recipient_text` for the user's own balance question would get `only_own_balance` instead of the balance. The twelve p7 runs show no such case (MAL-13 and CMP-09 pass), and the Learning data panel would show it as a `not_supported`/`other_balance` row whose masked text names nobody.
- **N2.** The guard fires only on `balance` plus `recipient_text`; a model that put the person in another field would not be caught. The prompt names `recipient_text` for exactly this, and the disclosure records three Flash parses of RED-10 carrying the name there.
- **N3.** `ParsedRequestValidator` does not require `unsupported_reason` to be null for a non-`unsupported` intent; a `balance` with a stray reason passes and the guard overwrites it. Pre-existing and harmless.
- **N4.** The `other_language` definition is now a 110-word parenthesis. It worked on four models (medians 98 to 100), so no change is asked; a future edit might split it into a sentence of its own, as `receive_from` and the own-number credit have.
- **N5.** The `other_language` rule keeps the stated fields filled (ADD-07: "Ali", 1,000,000). The orchestrator's `IsChooseAccountTransfer` and `IsPartOfBill` match on the reason, so a filled `other_language` request cannot slip into the transfer or bill paths; it ends in `AgentReply.Unsupported`.
- **N6.** The `deepseek-reasoning` entry inherits `Temperature` 0 from `deepseek` (asserted), with `MaxOutputTokens` 4,000 and `TimeoutSeconds` 90 for the reasoning tokens; `provider.data_collection` stays `deny`. The cost estimate prices output tokens at 0.5 USD/MTok, so a run's estimate is an upper bound; measured 0.0658 USD for three runs.
- **N7.** `EvalSettingsTests.TheDeepseekReasoningCandidateIsDeepseekWithReasoningAtLowEffort` pins position (`IndexOf("qwen") + 1`), every field equal to `deepseek` except the three changed, and the bound `ModelOptions` with no problems; it can fail on any drift. If `qwen` is ever removed the position check needs a new anchor.
- **N8. Test quality:** each new or changed test can fail and matches its claim. `OtherBalanceGuardTests` (six tests, `Assert.Same` for the pass-through cases, names from `SeedFacts`); `ConversationTests.ALatinScriptMessageIsRefusedAsOtherLanguage`; `PurchaseJourneys.ALatinScriptMessageIsRefusedAsOtherLanguage`; `ParsedRequestValidatorTests.UndoPaymentIsAReasonAndCreditToOwnNumberIsNot`; `LearningLogRuleTests.AnUndoPaymentRequestIsLoggedAsUndoPaymentLast`; `PhoneStringsTests.TheUndoPaymentReplyExistsAndTheOwnNumberCreditReplyDoesNot`; `ClaudeParserTests` version 7 and enum positions. `ScriptedParserTests.EveryBillOfTheSidecarNamesItsBillerInTheUsersOwnWords` is loosened for an unsupported request's `biller_text` but still requires it verbatim. `HelpJourneys` still counts five "not done" lines; no test asserts that each `Help_NotDone` line key exists in the resx (a missing key would render the key name), which `PhoneStringsTests` could pin in one assertion.
