## Findings

### Minor

**M1. `CopyButton` can import its module twice and leak one `IJSObjectReference`.**
- Where: `src/Agent.Web/Components/Phone/CopyButton.razor` line 35, `module ??= await JS.InvokeAsync<IJSObjectReference>("import", ...)`.
- What: `??=` tests `module` before the `await`; two taps before the first import resolves both see null, both import, and the second assignment overwrites the first reference, which is then never disposed. Microsoft's module pattern caches the *task* (`Lazy<Task<IJSObjectReference>>` or a `Task` field) so one import serves every call (learn.microsoft.com/en-us/aspnet/core/blazor/javascript-interoperability/call-javascript-from-dotnet, "JavaScript isolation in JavaScript modules"). Also the catch list names `TaskCanceledException` beside its base `OperationCanceledException` (harmless).
- Fix: `private Task<IJSObjectReference>? moduleTask;` then `moduleTask ??= JS.InvokeAsync<IJSObjectReference>("import", disposing.Token, path).AsTask(); var module = await moduleTask;` and in `DisposeAsync` dispose the awaited result when the task completed successfully. Optionally disable the button while a copy is in flight.

**M2. `ChatMessage` and `ConversationMessage` carry the whole code and keep the record-generated `ToString()`.**
- Where: `src/Agent.Web/Services/ChatMessage.cs` line 42 (`CopyText`, and `Text` for the `Purchase_code` message); `src/Agent.Core/Conversation/ConversationState.cs` line 113 (`PurchaseCode`).
- What: the milestone's policy, stated in `docs/failure-modes.md` line 155 and `docs/agent-core.md` ("a formatted log line cannot leak it"), was applied to `WalletOrder`, `PurchaseOrder` and `ConfirmOutcome.Done` but not to these two. No logger formats them today (the web project's only `LoggerMessage` is `WalletChanges.cs` line 59, exception type only; the runner's report holds no code), so this is defence in depth and consistency, not a leak; the nearest real path is a failing `Assert.Equal` over a `ConversationMessage` printing the record into CI output.
- Fix: override `ToString()` on both, printing `PurchaseCode`/`CopyText` as `***` (and, for `ChatMessage`, omitting `Text`, which is phone text by definition); one test each, as `WalletClientTests` line 673 does.

**M3. The type word's resource key is built from a wallet value; a type the resource file lacks would render the key name inside the phone.**
- Where: `src/Agent.Web/Components/Phone/OrdersPanel.razor` line 85 (`Text["Product_type_" + type]`); `src/Agent.Web/Services/PhoneFormat.cs` line 46 (`text["Product_type_" + type]`).
- What: `IStringLocalizer` returns the key itself with `ResourceNotFound = true` when no resource matches (learn.microsoft.com/en-us/aspnet/core/fundamentals/localization/make-content-localizable), so an unexpected `Product.Type` would show `Product_type_<x>`, an English non-resource text (rule 4). Bounded today: the wallet's `Product.Type` is an enum stored as a string (`WalletDbContext.cs` line 148) with `credit` and `internet` only, and the two keys exist; no test pins the pairing.
- Fix: read `var word = text["Product_type_" + type]; if (!word.ResourceNotFound) ...` and drop the word otherwise; add to `PhoneStringsTests` a check that every distinct `Type` in `SeedFacts.Seed.Products` has a `Product_type_<type>` key.

## Recommendations

- **R1.** `OrdersPanel.ProductLine` and `PhoneFormat.OptionLabel` fix the word order (operator name, type word, price) in code with spaces. In right-to-left text Khalil may want another order or a joiner; a template key (`Orders_ProductLine` and `Option_ProductLabel` with `{0} {1} {2}`) would make the order his, as every other phone line is, with no code change beyond the format call.
- **R2.** `PhoneFormat.Date` prints `yyyy/MM/dd`; Iraqi usage is commonly `dd/MM/yyyy`. Khalil's call, one format string; the time of day is dropped, which may matter when two orders fall on one day.
- **R3.** The copy button is silent on failure by design (ruling in the plan). `navigator.clipboard.writeText` requires a secure context (HTTPS or localhost) and a user gesture; on a LAN `http://` host every tap silently does nothing. Consider a `Purchase_code_copy_failed` key (Khalil's wording) shown for two seconds on `false`, and note the constraint in `docs/agent-web.md`. The code stays selectable in the DOM either way.
- **R4.** Ruling 3 left open whether the card should carry the type word. Options now do (`ZN-CR-10` vs `ZN-NET-10` are told apart), but the card the user confirms still reads operator, `Type_purchase`, price, so the last screen before the tap does not say credit or internet. Recommend adding it (a `CardSubject`/`CardView` field from the catalogue, rule 3 intact).
- **R5.** Ruling 4: `product_not_found` stays one template and NOGO-12's `available` field is `not graded`. The data is already in hand (`fitting` by provider in `ProductResolver`); a template with a code-built list is a small change if Khalil wants the reply to say what exists.
- **R6.** Ruling 5 sets no cap on My orders. The seed is small, but every read returns every order and renders one `CopyButton` (one JS import each) per row. If the demo grows, a `MaxOrdersShown` setting (configuration, in the settings panel) keeps the screen bounded.
- **R7.** `CopyButton` imports `./Components/Phone/CopyButton.razor.js` unfingerprinted while `App.razor` has `<ImportMap />` and `ReconnectModal` uses `@Assets[...]`. `MapStaticAssets` serves the plain path with no-cache validation so this is correct; routing the import through the import map would give the fingerprinted, immutable-cached file (learn.microsoft.com/en-us/aspnet/core/blazor/fundamentals/static-files, "Fingerprint client-side static assets"). Optional.
