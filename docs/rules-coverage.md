# Rules coverage

This table maps every rule in `docs/matching-rules.md` to the code that carries it out, the tests that show it, and the development cases (`data/requests.dev.jsonl`) that exercise it. There is one row per rule, in the order of that file: the 22 rules under "How a typed name is matched", the 19 rows under "Fees, limits and other values", and the six dated additions (three of 14/10/2026, one of 15/10/2026, two of 16/10/2026). It was surveyed on 16 Oct 2026 at commit `023249f`. Every class, method and test name below was read in the code or confirmed by a search. Rules are named by number or by row name, and cases by id. No Arabic is quoted.

**Implemented** is judged from the code, not from other docs. `yes`: the code does what the rule says, and a named test pins it. For a data or process fact, `yes` means the code or the seed enforces it and a test pins it, and the cell says which. `partial`: the code does part of the rule, and the clause names the missing part. `no`: no code carries the rule out. **Milestone** gives the `docs/build-plan.md` piece that builds the missing part. It is empty when the rule is fully built. **Dev cases** lists only the cases that reach the rule. `none` means no development case does.
