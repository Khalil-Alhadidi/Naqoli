# Milestone 6: Model In Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task (one implementer agent for the whole milestone, per Khalil's rule of 14 Oct 2026; the controller reviews each task's diff itself). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The real parser: phone and account numbers become tokens before any text leaves the process; one parse call per message through `Microsoft.Extensions.AI` returns a strict structure that code validates and treats as a request to check; invalid output becomes a question, never an exception or a card; a model outage shows the handover message; candidates switch by configuration; a baseline report on the development set is committed for every candidate before any prompt tuning, with time and cost per case; the learning log persists what milestone 5's rule derives; the chat uses the real parser and the journeys keep the scripted one.

**Architecture:** `Agent.Core` gains `Masker` (text → masked text + map; map → un-masking of a token the model returns), `ParsedRequestValidator` (strict structure → `ParsedRequest` or `Unclear`), `ClaudeParser : IParser, IParserUsage` built on `IChatClient` from the official Anthropic library (`Anthropic` NuGet, `AsIChatClient()`), with the prompt as an embedded English file and the output schema generated from a DTO (structured output, not forced tool choice), the `LearningLog` table and service, and the wallet-error ruling of 14 Oct. `Conversation` masks before parsing and un-masks after. `Agent.Eval` records the masked text (so the outbound check is real), reports usage and cost, takes `--parser`, and names reports by candidate. `Agent.Web` uses the real parser when a key is configured; the journeys host pins the scripted one.

**Tech Stack:** `Microsoft.Extensions.AI` 10.x (`IChatClient`, `ChatOptions.ResponseFormat = ChatResponseFormat.ForJsonSchema`), `Anthropic` NuGet 12.55.x (`AnthropicClient`, `AsIChatClient()`), `System.Text.Json` schema export, user secrets `Anthropic:ApiKey`, EF Core migration for the learning log, xunit.v3. Check the current package versions on nuget.org when adding them and record them in `docs/disclosure.md`.

**Spec:** `docs/build-plan.md` milestone 6 ("Done when"); `docs/architecture.md` sections 1 and 3, D1, D5, D7 (the model returns a list; this milestone parses one request and keeps the list shape for 9c), D13, D20, D21, D22; `CLAUDE.md` rules 2, 4, 5; `docs/matching-rules.md` (rules 9, 10, 19, 20 shape the slots; the Example column supplies prompt examples verbatim); `docs/reviews/milestone-3-security-review.md` I3 and "Forward-looking for milestone 6"; `docs/reviews/milestone-5-security-review.md` M1, M2, R3; the rulings in memory (`agent-decisions-14-oct` item 8: a wallet 5xx carrying a wallet `code` is "nothing taken"; a bare 5xx, timeout or dropped connection stays Checking); `docs/research/model-access.md`. ## Global Constraints

- Rule 5 is now a measured property: the text handed to the parser is the user's own words after masking plus the one-line pending note (`pending_card <type>` / `open_question <kind>`); nothing fetched from the wallet; no balance, contact name, alias, purchase code or PIN. - Rule 9: `Anthropic:ApiKey` lives in user secrets (`dotnet user-secrets set "Anthropic:ApiKey" ...` for `src/Agent.Web` and `src/Agent.Eval`) or the `ANTHROPIC_API_KEY` environment variable; never in the repository; the key is never logged.
- Khalil's wording: the prompt is English (Claude writes it); the Arabic examples in the prompt are copied verbatim from `docs/matching-rules.md`'s Example column and from `scripted-sentences.json` once Khalil fills it; Claude writes no Arabic. - Limits are configuration: `Model` section (`Candidate` name; `Candidates:<name>` with `Provider` `anthropic`, `ModelId`, `MaxOutputTokens` 400, `Temperature` 0, `TimeoutSeconds` 20, `InputPricePerMTok`, `OutputPricePerMTok`); `Agent:Parser` = `scripted` | `claude`; the settings placeholder shows them read-only.
- Cost awareness: before each baseline run the runner prints the estimated cost (cases × average tokens × price) and the real cost after; Khalil's budget is about 200 USD a month; a full dev run is expected to cost cents on Haiku and about one to three dollars on the larger candidates; the controller states the expected cost before dispatching the runs.
- Every package gets a `docs/disclosure.md` line in the same commit (the `Anthropic` NuGet and `Microsoft.Extensions.AI` and each model id used); every model becomes a disclosure line when first called. Every new failure mode a `docs/failure-modes.md` row. Build 0 warnings; small commits with the trailer lines; stage explicitly.
- Tests that call the real API are gated by `ZAINCASH_MODEL_TESTS=1` and skip otherwise; the suite stays green and free without a key.

- A masked token the model echoes (`<PHONE_1>`) un-masks to the typed number only from this message's map; a token not in the map is `invalid_number`. Test in Task 1.

**Interfaces:**
- `Masker.Mask(string text)` → `MaskedText(string Text, MaskMap Map)`: every run of 7 or more digits (ASCII or Arabic-Indic, with spaces, dashes or dots inside counted as part of the run, and an optional leading `+`) becomes `<NUM_n>` (n from 1 per message); the map keeps the original run; the masked text keeps everything else. `MaskMap.TryUnmask(string token, out string original)`. A `ParsedRequest.RecipientText` that is exactly a token un-masks to the original; one that contains digits (7+) which are not a token → `Refusal(invalid_number)` at the orchestrator (the validator rejects it earlier: see below).
- `ParsedRequestValidator.Validate(ParsedRequestDto dto, MaskMap map)` → `ValidationResult(ParsedRequest Request, string? Problem)`: enum strings must be in the fixed sets (`intent`: transfer, bill, purchase, balance, unsupported, unclear; `amount_unit`: none, dinars, thousand, million; `biller_code`: electricity, water, internet, school_fees; `product_type`: credit, internet; `unsupported_reason`: the ten documented); text fields ≤ 100 characters; `amount_value` ≥ 0 and finite; `product_value` > 0; `recipient_text` may be a token (un-masked here) or words with no 7+ digit run; any violation → `ParsedRequest { Intent = Unclear }` with `Problem` naming the field; the conversation records `LearningLogRule`'s `model_invalid_reply` entry when `Problem` is set.
- `LearningLog.WriteAsync(int userId, LearningEntry entry, string maskedText, ct)` stores the masked text (never the raw text; never a PIN; the masked text is what a person reviews, slide 2); `Conversation` calls it after every reply that yields an entry; the runner's derived entry stays the graded one (the table is additional).
- `WalletClient.ExecuteAsync`: 5xx with a parsed `WalletProblem` whose `Code != "no_code"` → `Refused(problem)`; document in `docs/wallet-api.md` ("a 5xx with a `code` means the wallet refused before writing; a bare 5xx means unknown").
