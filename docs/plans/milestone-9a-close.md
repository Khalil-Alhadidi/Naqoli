9. **Prompt caching on the parse call.** The static system prompt is marked cacheable through the SDK's `Microsoft.Extensions.AI` extension; the per-message user content is not. `ModelCandidate` (`src/Agent.Core/Parsing/ModelOptions.cs`) gains `CacheWritePricePerMTok` and `CacheReadPricePerMTok` (decimal, USD per million tokens, not below 0, validated with the two prices) and `PromptCacheTtl` (string: `5m` (the default), `1h` or `none`; any other value fails validation). Defaults in `src/Agent.Web/appsettings.json` and `src/Agent.Eval/appsettings.json` for every candidate, from the API's price list of 18 Oct 2026 (5-minute writes 1.25x the input price; reads 0.1x on Haiku 5.5, 0.05x on Sonnet 5.5 and Opus 5.5): haiku 0.125 and 0.01; sonnet 2.50 and 0.10; opus 5.00 and 0.20; `PromptCacheTtl` `5m` for all three. The console's settings panel shows the two new prices beside the existing ones and the TTL (read-only, as the Model section is). `ClaudeParser.ParseAsync`: the system message is `new ChatMessage(ChatRole.System, [new TextContent(Prompt).WithCacheControl(ttl)])` with `Ttl.Ttl5m` or `Ttl.Ttl1h` (`Anthropic.Models.Messages.Ttl`, the extension `Microsoft.Extensions.AI.AIContentCacheExtensions.WithCacheControl`), or the plain string message when the TTL is `none`; the user message is unchanged and carries no cache control. `ParseUsage` becomes `ParseUsage(int InputTokens, int OutputTokens, int CacheWriteTokens, int CacheReadTokens, decimal CostUsd, TimeSpan Duration)` where `InputTokens` is the API's `input_tokens` (the uncached part only; the API counts cached tokens separately). The counts are read from the SDK's own usage on `ChatResponse.RawRepresentation` when it is an `Anthropic.Models.Messages.Message` (`Usage.InputTokens`, `OutputTokens`, `CacheCreationInputTokens`, `CacheReadInputTokens`), else from `UsageDetails` (`InputTokenCount`, `OutputTokenCount`, `CachedInputTokenCount` for reads, `AdditionalCounts["cache_creation_input_tokens"]` for writes when present) so a wrapped client still reports. `ModelCandidate.CostUsd(long inputTokens, long outputTokens, long cacheWriteTokens, long cacheReadTokens)` prices the four counts. The parser's log line carries the two cache counts. `Agent.Eval`: `CaseDriver` sums the two counts per case; `EvalCommand` totals them over the run and writes `Model:CacheWriteTokens`, `Model:CacheReadTokens` and `Model:CacheHitRate` (cache reads as a percentage of all input: reads / (input + writes + reads), formatted `nn.n %`, or `n/a` when the denominator is 0) to the report header, and prints them on the "Model cost" console line; the estimate before the run is unchanged. Tests: `AnthropicAdapterTests` (the request body's `system` is one text block with `cache_control` of type `ephemeral` and, for `1h`, `ttl` `1h`; no `cache_control` on the user message; a response whose usage carries `cache_creation_input_tokens` and `cache_read_input_tokens` gives a `ParseUsage` with the four counts and the cost priced from all four; `none` sends no `cache_control`), the candidate validation tests (a negative cache price and an unknown TTL fail), `EvalSettingsTests` (the Eval settings still match the web's), and a unit test of the hit-rate formatting (`EvalCommand` or a small helper).
