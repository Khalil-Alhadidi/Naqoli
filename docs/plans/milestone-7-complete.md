**Design**
- `RepositoryRoot.Find(string? start = null)`: walks up from `start ?? AppContext.BaseDirectory` to the directory holding `ZainCashAgent.slnx`; `InvalidOperationException` when none. `EvalPaths.RepositoryRoot` calls it (keep `EvalPaths.SolutionFile` in sync or delegate).

Reads the dev set with `System.Text.Json` (`JsonDocument`; only `id` and `steps[].say` are used; nothing else is validated, that is `CaseLoader`'s job); reads the sidecar lines `{"id": "...", "step": <0-based index among the case's steps>, "say": "<exact text>", "parse": {"requests": [ ... ]}}` where `parse` is the exact structure the model returns (`ParsedRequestsDto`, snake_case, `JsonUnmappedMemberHandling.Disallow`). Load checks, each an `InvalidDataException` naming the id and step and never quoting text: a sidecar line whose (id, step) is not a `say` step of the dev set or whose `say` differs (ordinal) from the dev set's; a dev `say` step with no sidecar line; two lines with the same normalised masked text and different parse JSON. For each line: `Masker.Mask(say)` gives the map; every string field of each request has each masked original replaced by its token (so a typed number is a token, as the model returns it); `ParsedRequestValidator` validates the DTO against that map (as `ClaudeParser` does) and the resulting `ParsedRequest` (first request; the count traced as today by the caller is not needed here) is stored under `ArabicText.Normalize(masked text)`. `ParseAsync` looks the normalised text up as today; anything else is `Unclear`. The `ScriptedParser(IEnumerable<ScriptedSentence>)` constructor stays for tests; `EmbeddedSentences()` and the embedded resource go.
- `ParserFactory.AddAgentParser`: `scripted` registers the singleton `ScriptedParser.Load(path)` with the path resolved from `Agent:DevSetPath` against `RepositoryRoot.Find()` (resolved lazily, in the factory lambda, so a host without the repository still starts and fails only when the parser is first used; the error names the path).

**Design**
- `enum ReissueKind { TryAgain, SendAgain }`. `Orchestrator.ReissueAsync(int userId, PendingRecord previous, ReissueKind kind, ct)`: `previous.UserId` must equal `userId` (`ArgumentException` otherwise); rebuilds the `CardSubject` from the record (type, phone, account, display and registered names, bill account and code, product and code); re-reads what the checks need: a transfer re-reads the account by phone (a closed account refuses `account_closed`; a number gone refuses `number_has_no_wallet`); a bill re-reads the user's bills and takes the current amount due of the same bill account (0 → `nothing_due`, missing → `bill_not_found`); a purchase re-reads the catalogue product by code (missing → `product_not_found`) and takes its price; then the ordered checks and `CheckAndIssueAsync`, so a new record opens with a new ID, key and timer. For `SendAgain` the draft's `Warning` is `CardBuilder.RepeatWarning` whether or not the history rule set it. Trace `reissue` with `try_again` or `send_again`. The model is not called.
- `Conversation.ReissueAsync()`: allowed when a card is shown and its state is Expired, Cancelled, NotDone (`TryAgain`) or Done (`SendAgain`); refused and traced `reissue_rejected` when the state is Live or Checking or there is no card. Reads the record through `PendingStore`, calls the orchestrator in a fresh scope, shows the reply as any reply (a card message, a refusal). The latest card is the only one with a panel, so "only on the most recent card" holds by construction.
- `CardPanel`: when the card is not live: state Done shows `card-send-again`; Expired, Cancelled or NotDone show `card-try-again`; Checking shows neither. Disabled while `Session.Busy` or a click is in flight. `ChatSession.ReissueAsync` is the only web caller.
